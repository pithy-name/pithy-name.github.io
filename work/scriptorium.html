Scriptorium

A local-first personal knowledge OS with privacy-gated retrieval over 10,000+ notes. It started as a question about management, not software.

The repository is private — it holds a decade of my real working notes. This is the build story, plus the roadmap for the parts headed to open source.

It started as a Manager OS

The original question wasn't "how do I organize my notes" — it was what an operating system for a manager's judgment would look like. A decade of 1:1 notes, decision records, retros, hiring scorecards, and postmortems is a dataset about how a team actually worked — if you can query it. Mine was scattered across a handful of tools and thousands of files, and the only index was my memory.

The obvious answer — dump everything into a cloud AI tool — was the one I refused. These are other people's performance conversations and my own unfiltered working notes. So the defining constraint arrived before the first line of code: AI leverage without giving the data away.

The architecture is the privacy model

  • Local-first, deterministic-first. Parsing, routing, tagging, linking, and rendering are plain scripts — zero tokens, zero upload. The language model is reserved for the judgment calls scripts genuinely can't make: fuzzy segmentation, ambiguous routing, synthesis.
  • The cloud line is the LLM line — and it's explicit. Every operation is classified: either it's deterministic and never touches a model, or it's an LLM operation gated by sensitivity tier. Nothing crosses by accident.
  • Redaction before retrieval. All personal identifiers are pseudonymized by a deterministic pass (see the redaction tooling) before any content is eligible for model-facing work.
  • Hybrid retrieval, built honestly. Local embeddings + keyword search (BM25) fused by reciprocal-rank scoring, with metadata filters, over 10,000+ notes — and evaluated against real retrieval questions, because a search layer you haven't measured is a demo, not a tool.

What building it taught me

Scriptorium is also my hands-on lab for the questions I care about in the AI-tooling world: how embeddings behave on messy real corpora, when retrieval quality actually improves versus just changing, what a vector store means as a privacy surface in its own right. Shipping the hybrid retrieval layer roughly twelve weeks after adopting AI-assisted development is my favorite proof that the fastest way to learn a stack is to build something you personally need on top of it — while red-teaming every step, because the model writes bugs with the same confidence it writes everything else.

The public-subset roadmap

The vault stays private; the machinery doesn't have to. Pieces are being carved out, generalized, and published as standalone tools:

  • notion-to-obsidian — the ingest converter, already public.
  • The redaction pass — deterministic pseudonymization, being generalized for release.
  • The skills library — reusable AI-workflow definitions, on the same path.

The pattern in all three: the part worth sharing is never the personal data — it's the discipline around it.
